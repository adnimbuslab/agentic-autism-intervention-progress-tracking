## Cross-file findings worth carrying into later phases

1. **Duplicate/divergent pipeline implementations**: `observation_service.py`'s `_run_pipeline`/`_handle_routing` and `observation_workflow.py`'s LangGraph `StateGraph` both implement the same extract→validate→route→dispose pipeline. A repo-wide grep confirms `observation_workflow.py` is never imported/called anywhere else — it is dead code, and it is also functionally less complete than the live imperative path (its `clarify_node` doesn't select/generate clarification question text). CLAUDE.md names LangGraph as the intended agentic framework; the live code path doesn't use it.
2. **Inconsistent transaction-commit ownership**: `report_service.py` calls `db.commit()` itself; `observation_service.py`, `workspace_service.py`, `schedule_service.py`, `audit_service.py`, `analytics_service.py` only `db.flush()` and leave commit to a caller. Worth reconciling once the API layer is mapped.
3. **Middleware ordering in main.py**: `RequestIDMiddleware` is added after `CORSMiddleware`, making it the outermost layer — its own raw 500 error responses on unhandled exceptions bypass CORS header injection. Possible real bug (src/backend/main.py lines 76, 115).
4. **RBAC/child-authorization enforcement is not visible in this scope**: `workspace_service.list_children` takes a pre-computed `authorized_child_ids` list rather than computing it; the actual authorization logic must live in `src/backend/api/deps.py` or the API routers (out of scope for this sweep — worth checking in the API-layer sweep to validate CLAUDE.md's "child-level RBAC enforced at both UI and API layers" claim).
